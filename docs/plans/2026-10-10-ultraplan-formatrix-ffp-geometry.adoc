branch, not a completed or merged change. Keep the work separated and do not

== Binding rules and authority

Use the status of each source, not just its location in the estate:

* **FFP 1.0.0** is active and ratified (2026-10-04). Its MARKER producer
  obligations are normative. FFP says a producer that wrote any field value
  MUST set `ffp:filledBy=machine` in an XMP packet in the PDF catalog's
  `/Metadata`; it MUST preserve, not remove or overwrite, existing XMP. FFP
  recommends appearance generation, but that recommendation is not the marker
  obligation.
* **SEAMS-SPEC 1.0.0** is active and normative. Its seam register belongs in
  the canonical Trustfile at
  `.machine_readable/contractiles/trust/Trustfile.a2ml`; it requires a local
  P2P `test_ref`, and says a Mustfile `seam-check` must run the P2P test until
  the planned `contractile trust verify` exists.
* **DocMatrix#71** is the live composition contract and the current owner ruling
  is controlling: products remain independently useful and own their schemas;
  Groove handles discovery/compatibility; bootstrap is static typed
  records/direct invocation; do not introduce another runtime integration
  engine. ForthWall remains proposed and audit/propose/verify-only.
* **Blocky Writer's own contractiles remain binding.** `INTENT.contractile`
  says the WASM boundary is exactly two functions, filling is name-driven, and
  page geometry is never silently transformed. `MUST.contractile` forbids new
  TypeScript/Python/Go and NPM dependencies, removal/weakening of tests or CI,
  loss of `.machine_readable/`, and unapproved unsafe Rust. PDF-defined
  interpretation of `/Rect` corner order is not a screen/page transform; no
  other normalization is introduced.
* **Standards proof policy is binding.** The current
  `hyperpolymath/standards/3-practice/PROOF-POLICY.adoc` maps first-party Rust
  code to Creusot, API/ABI engineering properties to Idris2, and mathematical
  theory to Agda, with theory proofs rechecked in Rocq and Lean. Third-party
  `lopdf` code is not edited or re-proved; behavior relied on at that boundary
  is recorded as an assumption with version and evidence.
* **Mathesis Grade 3 is an evidence status, not a test grade.** The estate
  mathematics architecture defines Grade 3 as a claim that type-checks locally
  in Agda but has not been translated to an independent foundation. Mathesis
  `T3 — Standard` is a separate repository proof-tier label. Mathesis catalogs
  receipts while source repositories retain proof ownership. This PR's Rust CI
  tests are `TESTED` evidence only: no formal proof artifact exists here, so no
  Grade 3 or `PROVEN` claim is made. To satisfy the requested Grade 3 proofing,
  formalizable theory claims need a locally checked Agda witness; code and ABI
  obligations still follow the Standards verifier mapping.
* **The A2ML/DEED format position is unresolved.** Current standards A2ML
  `meta`, `state`, and `ecosystem` documentation carries a warning that the old
  TOML-like characterization is superseded and points to DEED. But
  `DEED-GRAMMAR-SPEC.adoc` v0.2.2 explicitly says DRAFT and not ratified. Do
  not present the old TOML-like examples as current conformance grammar, and do
  not present the draft DEED grammar as ratified. This is a standards-owner
  decision gate, not permission to infer a universal parser from local files.
* `0-canon/rsr/RSR-SPEC-v2.adoc` in the standards checkout is explicitly DRAFT.
  Do not cite it as a ratified requirement. The current RSR template's executable
  minting/conformance scripts and the open template issue are evidence for the
  narrowly scoped follow-up below.

== Work package 1 — FFP producer and declared seam

=== Goal

Make Blocky Writer's filled output honestly declare machine-written field
values under ratified FFP 1.0, preserve existing metadata, and provide a
runnable producer-to-Presswerk seam test without adding runtime coupling.

=== 1A. Producer behavior

Implement within the existing `fill_blocks` path; do not add a WASM export or a
new runtime service.

* Track actual successful field writes. Add the FFP marker only after the fill
  operation has successfully written at least one value. The marker belongs in
  an XMP packet carried by the catalog `/Metadata` stream, never `/Info`.
* Use the FFP 1.0 namespace URI exactly and set `ffp:filledBy=machine`. The
  optional `ffp:tool` SHOULD identify `blocky-writer`. Omit `filledAt` and
  `toolVersion` in the first pass: neither is required, the former is
  privacy-bearing, and Presswerk's release-preparation note recommends consent
  before emitting `toolVersion`/`filledAt`.
* The current writer does not generate `/AP`. If it emits
  `ffp:appearancesGenerated`, it must be `false`; do not declare `true` based
  only on `/NeedAppearances` or pre-existing streams. Keep the blank-print
  hazard visible to Presswerk.
* Preserve all existing XMP content. Add/merge the FFP description without
  replacing unrelated RDF, namespaces, or packet data. If an existing packet is
  malformed or cannot be safely merged, fail with a structured `BW_*` error
  rather than silently replacing it. If a pre-existing FFP declaration
  conflicts with the new producer metadata, get a standards-owner resolution
  before choosing overwrite/duplicate semantics.
* Define no-op behavior explicitly. `fill_blocks_impl` currently sets
  `/NeedAppearances=true` before it knows whether any supplied field matches;
  an empty fields map can therefore serialize a mutated document with zero
  field writes. Tests must establish whether this is retained or corrected, and
  prove that no new FFP marker is asserted when no field value was written.

=== 1B. Producer-side tests

Add narrow tests for the marker and metadata semantics, including:

[cols="2,3",options="header"]
|===
| Input case | Required assertion

| Successful text/select write
| Catalog `/Metadata` contains FFP namespace + `filledBy=machine`; no new
  `/Info` claim.

| Successful button write
| The same marker condition holds for `/V`/`/AS`-based writeback.

| Existing non-FFP XMP packet
| Existing packet content survives and FFP is added; it is not replaced.

| No matching/empty values or fill error
| No false machine-filled declaration is added; error paths do not return a
  partially serialized output.

| Existing malformed or conflicting FFP metadata
| No silent metadata loss. The approved policy is exercised and the failure is
  structured if safe merge is impossible.

| Appearance declaration
| If present while Blocky Writer still relies on `NeedAppearances`, the value is
  `false`; tests do not imply that `/AP` was generated.
|===

Also run the standards FFP detector conformance vectors where available, but
label them correctly: the existing shared 14-vector runner verifies a
*detector's classification semantics*. It does not by itself prove that
Blocky Writer writes a conforming marker or that its actual output crosses the
Presswerk seam.

=== 1C. Seam declaration and P2P gate

The seam ID is `blocky-writer-presswerk-form-handoff`. The FFP PRINT-PATH
worked example supplies the intended direction, `fail-degrade` behavior, and
`external-trust` tier. Both product repositories need their own declaration in
the canonical Trustfile; the inspected Blocky Writer and Presswerk Trustfiles
currently lack the entry.

There are standards-example mismatches that must be resolved rather than copied
blindly:

* SEAMS-SPEC requires `contract` to be a path relative to the repository root
  and `test_ref` to name a local, runnable P2P test.
* FFP PRINT-PATH's worked example points both fields at paths in the separate
  `standards` checkout; its conformance runner exercises detector vectors and
  is not a test of a Blocky Writer-produced PDF passing through Presswerk.
* FFP's example pairs `failure_mode: fail-degrade` with `tier: external-trust`,
  while SEAMS-SPEC §7 says `fail-degrade` seams require `elixir-disciplined`
  tier or higher. The intended tier ordering/exception for this handoff is not
  established by the inspected texts.
* SEAMS-SPEC also says `external-trust` seams must be isolated by a circuit
  breaker. The FFP handoff is a PDF/file handoff, not an identified network
  service; requiring a new runtime circuit breaker may conflict with DocMatrix#71
  and is not justified by current evidence.

Ask the standards owner to clarify how a child repository pins an external FFP
contract under SEAMS-SPEC, whether the FFP example's test reference is intended
as the local P2P test, how its tier/failure-mode pair is reconciled with SEAMS-SPEC
§7, and whether the circuit-breaker clause applies to this file handoff. Do not
duplicate or silently fork the standard. Do not build a runtime circuit breaker
to paper over the ambiguity. Subject to an owner-approved interpretation,
create an in-repository P2P test that:

. produces a deterministic filled AcroForm fixture using Blocky Writer;
. passes that output to Presswerk's detector/print-path classifier (for example,
   via a test-only `FFP_DETECTOR` interface); and
. asserts declared machine-filled provenance and preserves any incomplete
   appearance hazard.

The test is test-only. It must not add Presswerk as a runtime dependency, make
Presswerk mandatory to use Blocky Writer, or create another integration engine.
Coordinate the matching declaration/test in Presswerk through its maintainers;
this plan does not modify that repository.

The Blocky Writer seam record must include the fields required by SEAMS-SPEC:
`id`, `description`, `from`, `to`, `contract`, `test_ref`, `failure_mode`,
`tier`, and `notes`. Resolve the contract/test path discrepancy first; then wire
the P2P test into the current Mustfile/CI mechanism. The inspected
`contractiles/must/Mustfile.a2ml` contains only license/readme/banned-path checks,
not `seam-check`, and the inspected `.machine_readable/MUST.contractile`
references `quality.yml`. Confirm the active runner mapping before asserting
that CI already enforces SEAMS-SPEC. Until a real seam gate runs, record the
deferral honestly rather than claiming conformance.

== Work package 2 — detection tests, geometry, and field identity

=== Goal

=== 2A. Test the current detector directly

Implementation revision `9f9370e` has 22 test functions using synthetic

=== 2B. Resolve the contract before changing behavior

The composition contract forbids silent geometry transformation. PDF `/Rect`
semantics permit the two diagonal corners in either order, so the detector's
`min`/`max` step is the format-defined interpretation required to produce
`{x,y,width,height}`—not an application-side coordinate repair. Revision
`9f9370e` applies that rule, resolves chained indirect rectangle and numeric
references with cycle protection, widens `Block` coordinates to `f64`, and
rejects missing, unresolved, malformed, non-finite, or unrepresentable widget
geometry with `BW_PDF_WIDGET_RECT_INVALID`. Null or dangling optional
annotation entries remain absent, matching existing behavior. This
implementation has remote Rust CI evidence, but geometry and compatibility
owner review remains open; treat the behavior as provisional until that review
is recorded.

Before closing the contract gate, agree on:

. the PDF `/Rect` pair semantics and refusal behavior for malformed geometry;
. the coordinate reference frame and units (raw PDF user space, with no screen,
  page-rotation, or page-box transform in this response);
. page identity and ordering, including whether a future version returns page
  numbers or hierarchical field identity;
. `f64` range/rounding behavior and the three new public error codes; and
. text decoding/normalization rules for PDF field names and display labels.

The PR bumps `pdftool_core` to `0.2.0` to mark its breaking numeric/error
contract. Keep exactly the existing two WASM exports; do not expose a rounded
