= pdftool_core

Rust/WASM core for `blocky-writer`.

== Implemented

* `detect_blocks` parses PDF AcroForm widget annotations and returns their
  labels and rectangles. It does not perform OCR or general-purpose visual
  block detection.
* `fill_blocks` updates matching AcroForm field values and returns serialized
  PDF bytes. It supports the field types and validation covered by the unit
  tests; it is not a PDF renderer.
* Synthetic-PDF unit tests in `src/lib.rs` cover representative widget detection,
  rectangle/annotation validation, and selected `Tx` / `Ch` / `Btn` writeback
  paths. They are not general PDF conformance tests or real-world corpus
  coverage. The detector additions in the current session branch still require
  formatting, compilation, tests, and Clippy before they can be called verified.

== Native development checks

From the repository root:

[source,bash]
----
cargo fmt --manifest-path rust/pdftool_core/Cargo.toml -- --check
cargo test --manifest-path rust/pdftool_core/Cargo.toml --locked
cargo clippy --manifest-path rust/pdftool_core/Cargo.toml --locked --all-targets -- -D warnings
----

== WebAssembly packaging

Install Rust with the `wasm32-unknown-unknown` target and `wasm-pack`, then run:

[source,bash]
----
scripts/build-wasm.sh
----

The extension frontend currently has no checked-in compiler/package manifest or
reproducible bundle build. The `.affine` source files are a prototype and are
not presently wired into a verified extension build. Do not treat the frontend
as a release-ready browser extension until that toolchain and its integration
tests are established.
